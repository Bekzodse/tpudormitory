Smart Dormitory

A full-stack dormitory portal & ERP for Tashkent Perfect University. How students book rooms, how admins run operations, and how the parts talk to each other.

local · localhost:4173 · Node 22 / Java 21
THE PRODUCT

What students and admins can do

One unified platform covering student room discovery, online booking, live chat, and 12-module dormitory ERP operations.

Accounts & Student Portal
Register with course & phone, upload an avatar, track room assignment, and stay logged in for 7 days.
Room Catalog & Booking
Browse 2-, 4-, and 6-bed rooms, compare features, pick a preferred room number, and submit a booking online.
Live Support Chat
Booking automatically opens a chat thread with dorm administration, complete with unread counters and history.
12-Module Admin ERP
Manage floor maps, approve bookings into rooms, track monthly payments, maintenance tickets, and audit logs.
Dynamic CMS & Gallery
Edit homepage copy, KPI stats, hero photos, gallery categories, facilities, and FAQs without touching code.
In-App DB Studio & Parity
Inspect and edit all 19 SQLite tables from the admin panel, backed by both Express 5 and Java 21 servers.

THE API

75 endpoints, one predictable contract

Every endpoint lives under /api and returns structured JSON. The same contract runs on both Express 5 and Java 21.

Area Paths Who may call
Auth (5) /auth/register, /login, /logout, /me, /profile Anyone / Logged in
Public (7) /rooms, /homepage, /gallery, /faqs, /bookings, /contact Anyone
Portal & Chat (4) /student/portal, /maintenance, /support/chat, /message Students
ERP Core (19) /admin/overview, /bookings, /rooms, /dorm-rooms, /residents Admin only
Finance & Ops (9) /admin/payments/bulk, /maintenance, /announcements, /messages Admin only
Support Chats (8) /admin/chats, /:id/reply, /:id/read, /messages/:msgId Admin only
CMS & Media (17) /admin/homepage, /facilities, /faqs, /gallery, /upload-image Admin only
Audit & DB (6) /admin/activity-logs, /accounts, /database/:table/rows Admin only

Same rules everywhere

  • JSON bodies up to 15 MB for base64 room, hero & gallery photo uploads.
  • Passwords hashed with salted 64-byte scrypt and timingSafeEqual checks.
  • HttpOnly, SameSite=Lax cookie lasts 7 days with automatic sliding refresh.
  • All /api/admin/* routes pass through requireAdmin (401 or 403 otherwise).
  • Positive-integer validator rejects malformed :id, :chatId & :msgId params.
  • Every admin create, edit, delete & contact writes to admin_activity_logs.
  • Global error handler maps SQLite constraints & bad JSON to clean codes.

DELIVERY & RUNTIME

From local dev to dual-runtime production

1

Dev runner

npm run dev launches backend/index.js (--watch) alongside Vite dev servers on 5173 & 5174.

Vite bundle

npm run build compiles React 18, Lucide icons, GSAP & styles into static assets in dist/.

3

Auto-migrate

4

Dual runtime

SAFETY NETS

Where the data lives, and what protects it

SQLite WAL + busy timeout
auth.sqlite runs in Write-Ahead Logging mode with a 5-second busy timeout, allowing concurrent reads during writes safely.
scrypt + AES-256-GCM
User passwords are salted and hashed with 64-byte scrypt and checked via timingSafeEqual; sensitive fields use AES-256-GCM.
DB-backed 7-day sessions
Tokens survive server restarts in the sessions table, expire automatically, and travel only in HttpOnly, SameSite=Lax cookies.
Strict Admin RBAC
Every /api/admin/* route verifies both active session and role === 'admin' + verified === 1 before touching any record.
Full Audit Activity Log
Every admin create, update, delete, and client contact call logs actor, timestamp, section, and summary to admin_activity_logs.
Input & Crash Shields
Positive-integer param validators, 15 MB payload limit, image extension whitelisting, and unhandledRejection guard keep API alive.
HOW IT WAS BUILT

An iterative full-stack loop, one module at a time

Architectural principles

Clean module boundaries

Student frontend, 12-tab Admin ERP, Dashboard widgets, and Backend APIs live in dedicated folders.

Zero-downtime auto-schema

Every new feature adds idempotent CREATE/ALTER checks and safe seed defaults on startup.

Dual-backend parity

Both Express 5 (Node.js) and Java 21 HttpServer mirror the same routes, cookies, and data model.

Every module ships end-to-end: SQLite table → API CRUD → Admin ERP tab → Public UI sync.
